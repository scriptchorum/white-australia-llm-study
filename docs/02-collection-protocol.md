# 采集与隔离规范

版本：0.1，未实施。目标为控制并记录客户端输入边界，不是清除模型的预训练知识或控制供应商全部内部服务。

## 每题独立请求

每次只发送该条prompt_text，以及B组该题固定的史料全文。每题重建消息/输入对象，不追加上一题回答。不使用自动记忆、共享会话、检索库、搜索或会自动补充上下文的代理框架。

OpenAI不连接既有conversation，不传previous_response_id，也不把历史手工塞回input。DeepSeek每次重建messages，不复用会持续追加历史的列表。两模型不能看到对方答案；中英文请求各自独立，不能将英文回答作为中文题的翻译输入。基础题与备选诊断也不构成连续追问。

不发送论文、研究假设、审稿意见、编码规则、参考答案和观察点。JSON中的ID、condition、claim_mapping和observation只供研究者记录，不能意外序列化成模型输入。实际请求保存后逐项确认其消息角色和全文。

无需为每题重新注册账号。隔离依赖实际发送的上下文及状态连接，而不是“换账号”这一形式。

官方机制参考：

- [OpenAI会话状态](https://developers.openai.com/api/docs/guides/conversation-state)
- [DeepSeek多轮对话](https://api-docs.deepseek.com/guides/multi_round_chat/)

## 系统设置与工具

不加入后殖民历史学家、道德裁判等角色。如端点允许，仅使用规定的用户提示；如必须或决定使用额外指令，则在采集前固定全文和角色，双语版本保证功能对应。记录所有客户端实际发送的指令。供应商不可见指令不推定为空。

不配置联网、搜索、文件检索、知识库、函数工具或应用记忆；记录实际工具配置。API存储设置是数据保留问题，不等同于会话隔离；不能仅因设置store=false就声称不存在历史上下文。

## 固定型号与生成配置

在configs/collection-config.template.json的本地副本中填写真实API模型名、实际返回模型名、端点、模式、设置和日期。不可见或不支持字段明确标记not_exposed或unsupported，不虚构默认值。

优先考虑支持的非思考/无额外推理设置以控制任务与预算，最终配置须按两个具体端点核实。相同temperature、token上限或effort名称不保证计算条件等价；不要为强行一致发送不受支持参数。低温不等于完全确定，也不能隔离训练原因。

不在批次中途因答案改变设置。明确更新版本或模式时暂停该批次，记录并另立批次；不悄然合并。

## 执行顺序与时间窗口

先生成包含prompt_id、model、language、batch和sequence的运行清单，并保存随机排列及产生方法。按模块平衡安排模型和语言，避免先采完某一模型或语言，再隔很久采另一组。随机化控制的是时间和执行顺序，不能替代上下文隔离。

同一批次尽量在短时间窗口完成。服务变化、限流或中断记录实际时间及恢复点，不覆盖已得回答。不为填满数量而替换题材。

## 技术失败与结果处理

超时、空响应、明确技术错误和完成状态表明的截断可作技术失败；最多追加两次技术重试，保留所有尝试及错误码，使用首个技术有效回答。仍失败则报缺失。

拒答、纠正前提、不同意研究假设、短答、不符合目标字数或出现反例都是研究结果，不按技术失败重试。自然结束的简短回答不猜作截断。语义错误和幻觉先留存再分析。

试采集与正式批次分开；若提示、材料、配置或编码改变，记录版本，不把旧试采集伪装成定稿数据。

## 隔离验收

实际请求只含当前题目、固定指令和该题规定材料；无历史、无另一模型答案、无前一语言答案、无论文假设或分析标签、无工具。请求/响应身份可追踪，材料与提示版本能核对。技术验收通过不等于结果支持理论。
