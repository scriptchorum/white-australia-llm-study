# 采集与隔离规范

版本：0.2。每个请求构建独立输入，完整保存实际发送的内容。

## 输入与会话

每题重新建立消息对象，只包含当前prompt_text、固定指令及B组指定材料。两个模型、两种语言和每道诊断题各自独立请求。OpenAI的历史会话关联字段留空；DeepSeek每次重建messages。

研究标签、观察点和编码手册留在分析端。请求端只提取prompt_text和规定材料。客户端工具列表留空，采集流程直接调用API。

系统或开发者消息在冻结前确定全文与角色，选择最简、功能对应的设置。供应商隐藏设置记为不可见。数据保留设置和上下文关联分别记录。

参考：[OpenAI会话状态](https://developers.openai.com/api/docs/guides/conversation-state)、[DeepSeek多轮对话](https://api-docs.deepseek.com/guides/multi_round_chat/)。

## 配置

在配置模板的本地副本中填写端点、请求模型、返回模型、模式、采样设置、输出上限和时间。参数状态使用supported、unsupported或not_exposed等实际记录。

优先核实非思考或最简推理设置。参数的数值和实际含义一并登记。比较时解释两家服务设置的对应关系；供应商升级或模式变化形成新批次。

## 顺序与时间

生成运行清单，记录prompt_id、模型、语言、批次和sequence。保存随机化方法与顺序，平衡安排模型、语言和模块，集中在短时间窗口采集。

## 重试

超时、空响应、明确技术错误和技术截断最多追加两次尝试，保留全部记录，采用首个技术有效回答。持续失败记为缺失。

拒答、纠正前提、短答、字数偏离和反例均进入分析。提示或设置调整后记录新版本，试采集和正式数据分开保存。

## 验收

核对请求全文、角色、工具配置和历史关联字段；确认输入对应当前题目。逐项检查模型身份、材料版本、响应状态和请求ID，形成可恢复的记录链。
